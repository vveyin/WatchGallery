# 相册 · WatchGallery

一款专为 **Android 11 圆屏手表**（运行完整 Android，非 Wear OS）设计的相册应用。UI 风格借鉴 GitHub 用户 vveyin 的 `f-x` 仓库（Material Design 3、圆表盘自适应、旋转表冠操作、夜间/白天双主题），相册与编辑功能对标手机相册（参考 Fossify Gallery、ImageToolbox）。

## 功能

### 相册
- 通过 MediaStore 扫描设备全部图片，按文件夹（相册）分组
- 圆屏 2 列 / 方屏 3 列网格自适应，图片安全区避让表盘边缘
- 大图查看：双指缩放、单指平移、双击复位、左右切换、旋转表冠缩放
- 权限申请（Android 13 `READ_MEDIA_IMAGES` / 低版本 `READ_EXTERNAL_STORAGE`）

### 图片编辑（对标手机相册）
- **滤镜**：原图 / 黑白 / 怀旧 / 鲜艳 / 冷色 / 暖色 / 反色
- **调节**：亮度、对比度、饱和度、色温
- **裁剪**：拖动选择区域
- **涂鸦**：多色画笔、粗细、撤销、清空
- **旋转/翻转**：90° 旋转、水平/垂直翻转、重置
- **保存**：通过 MediaStore 存入 `Pictures/WatchGallery`，无需存储权限（API 29+）

### 主题与交互
- Material 3 主题，夜间（默认黑底）/ 白天（白纸）/ 跟随系统三态切换，设置页可选
- 沉浸式全屏，表盘安全区自适应（借鉴 f-x 的 WatchMetrics 弧宽/短边缩放思路），所有页面内容约束在内切圆内
- 旋转表冠 / 滚轮 / 方向键 / 音量键多路上报

### 设置（v0.1 新增）
- **表冠适配**（完整借鉴 f-x 的两种模式）：
  - `OPPO`：走普通 MotionEvent 滚轮轴，不过滤 action/source（OPPO 系表冠 source 位不可靠）
  - `华为 / 三星`：走 `ACTION_SCROLL` + `SOURCE_ROTARY_ENCODER`，原始值 ×15 拉齐手感
  - **灵敏度**：0.1x ~ 10.0x，**对数轴**调节（0.1→1 与 1→10 拨动距离相同，低频段也能细调），乘在原始滚动量上，改完即时生效并持久化
  - **表冠测试**：页内实时显示收到的表冠事件，便于确认哪种模式适配你的表（v0.2）
- 主题设置：夜间 / 白天 / 跟随系统

### 稳定性修复（v0.2）
- **权限检测**：每次回到前台重新探测；被拒且「不再询问」时提供「去系统设置」入口；空相册可「重新扫描」
- **读不到照片兜底**：MediaStore 缺列不再导致整表为空；额外直接扫描 `Pictures/DCIM/Downloads` 常见目录
- **表冠 OPPO 模式**：修复增量被累加成总位移导致滚到底后失效的问题，改为逐条事件流投递；旋转编码器式表冠自动增益

### 相册空白修复（v0.3）
- **布局根因**：标题栏的安全区容器 `fillMaxSize` 放在 `Column` 里会吃掉整屏高度，网格高度被压成 0，看起来就是"照片列表是空的"。现在整屏统一套安全区，标题 wrap content、网格 `weight(1f)`
- **安全区改为几何正确**：圆内最大可完整显示的区域是以圆心为中心的正方形（≈0.707×直径），不再只是加 padding 导致四角被弧边切
- **读取照片五级兜底**：images 表逐卷查询 → files 表 `media_type=IMAGE` → 主动触发系统媒体扫描（adb push 的照片不进媒体库）→ 目录直扫 → 应用内导入目录
- **手动导入**：空相册可直接用系统文件选择器导入照片，内容复制进应用私有目录，永远读得到
- **扫描诊断页**：设置 → 扫描诊断，展示权限、媒体库行数、目录命中、异常信息

### 滑动快捷多选支持反向取消选择（v0.30）
- **同一个滑动手势既能加选也能取消**，不用换按钮、不用进二级菜单：
  - 从**未选中**的照片起手横滑 → 滑过的照片全部**选中**
  - 从**已选中**的照片起手横滑 → 滑过的照片全部**取消选中**（手机相册同款）
  - 判定在手指按下那一刻做一次，整个手势过程不翻转
- 长按进入多选后的第一段滑动固定为加选（长按本来就是「从这里开始选」的动作），
  松手后再滑才按起点状态决定加选 / 取消
- `addSelected` / `removeSelected` 只在选中集合真的变化时才写 state，
  取消滑动扫过一大片未选中的照片不会触发无谓的全列表重组
- versionCode=30 / versionName=0.30

### 多选交互重做：长按即滑、点照片看大图、点圈才选中（v0.29）
- **长按后就地滑动多选**：长按成立的那一刻，手指**不用抬起**，直接滑动就是普通快捷多选；
  松开后再滑也是同一套逻辑。以前是「长按后走矩形选取，松手后走另一套」，两套判定行为不一致
- **两套手势合并成一份实现** `runSelectionDrag()`：长按接续与多选覆盖层共用，规则完全对齐
  - 横向滑（45° 分界）＝ 起点到当前点的矩形覆盖到的照片全选
  - 纵向滑 ＝ 滚动列表
  - 横向锁定后再纵向滑，仍只是扩大选取范围，不会切成滚动
- **多选里点照片 = 打开大图查看**，**点右上角复选圈 = 切换这张的选中状态**（手机相册同款）
  - 复选圈热区 40dp 直径，圈中心距照片右上角 16dp；照片本体判定留 22dp 容差，
    抵消行缩放（中间 1.10 / 边缘 0.78）造成的边界误差
- versionCode=29 / versionName=0.29

### 修复「松手才卡、几秒后崩溃」的真凶：awaitEachGesture 空转 + 主线程看门狗（v0.28）
- **根因**：`awaitEachGesture` 的内部实现是 `while (isActive) { awaitPointerEventScope { block() } }`。
  v0.27 的拖动接续协程在 block 的**第一行**就写了 `if (selectionMode) return@awaitEachGesture`，
  于是在多选模式下 block 还没碰到任何挂起点就返回，下一轮立刻再次调用它 —— 变成**没有挂起点的
  忙循环**，把 `AndroidUiDispatcher.Main` 彻底占满。
  - 手指按着时协程正挂在 `awaitPointerEvent` 上，所以拖动过程还看着正常；**一松手**循环就开始空转，
    屏幕上每个可见单元格各跑一个 → 界面立即卡死，几秒后 ANR，系统杀掉进程，日志里只剩 `START`
  - 修复：把 `awaitFirstDown()` 提到状态判断**之前**，保证每一轮 block 至少挂起一次等手指按下；
    多选模式下直接 return 只是「等下一次按下」，不再空转
- **新增主线程看门狗** `util/MainThreadWatchdog.kt`：ANR 不经过 `UncaughtExceptionHandler`，
  所以卡死永远抓不到堆栈。现在后台守护线程每 1s 往主线程投一次心跳，超过 2.6s 未执行即判定阻塞，
  抓取主线程堆栈写入崩溃日志并置位 `crash.pending`，下次启动的崩溃报告页就能直接看到卡在哪一行
- versionCode=28 / versionName=0.28

### 冷启动自动更新检测 + 修复长按多选卡死（v0.27）
- **冷启动自动检查更新**：打开 App 时自动检测新版本，只在**进程第一次启动**时执行
  - 从后台回到前台不会重建 Activity，天然不触发；配置变化重建时由进程级标记拦住
  - **先判断联网**：无网络时完全静默（不提示、不弹窗、不跳页）
  - 有网才请求 Release；确认远程版本更新后直接进入更新页，页面立刻显示「发现新版本 + 下载更新」
  - 新增 `ACCESS_NETWORK_STATE` 权限；`UpdateChecker.isOnline()` 用 `NET_CAPABILITY_INTERNET` 判断
  - 启动后延迟 900ms 再查，避免和相册扫盘抢 IO
- **修复长按多选后卡死、几秒后崩溃（v0.26 引入）**，两处根因：
  - `withTimeoutOrNull` 包住 `awaitPointerEvent` 计算长按：超时会取消指针输入协程，Compose 事件分发卡住 → ANR。改为**不用超时**：拖动接续的协程只观察事件，等 `detectTapGestures` 的 `onLongPress` 置位后再接管消费
  - 长按进入多选时 `userScrollEnabled` 从 true 翻到 false，等于在手势中途重建滚动节点，会打断正在进行的指针手势。改为恒为 true（多选时覆盖层已经消费全部事件，网格本来就滚不动）
  - 另：矩形选取改为只上报「本次手势新命中的照片」，避免每个移动事件都重建选中集合
- versionCode=27 / versionName=0.27

### 设置配色 / 长按直接拖选 / 图片名开关（v0.26）
- **设置条改淡灰底**：所有设置行、二级选项由 primary 紫蓝填充改为 `surfaceVariant` 淡灰；选项的「已选中」改为淡灰底 + primary 描边与文字，保留可辨识度但不再整页紫蓝
- **长按直接拖选**：长按照片不松手，直接滑动即可多选，**横向纵向都可以**（矩形覆盖即选中）

  - `pointerInput` 的 key 只用 uri，多选状态翻转不会重启手势协程（否则长按后拖动会断掉）
- **横向间隔减半**：网格 `horizontalArrangement` 8dp → 4dp，列宽随之变大、照片更大；左右 contentPadding 不变，整排外沿位置不变
- **图片名开关**：设置新增「显示图片名」，关闭后照片不再渲染底部文件名条（默认开）
- **底部多选栏改图标**：删除键只留垃圾桶图标（无文字）、取消键改为标准返回箭头
- versionCode=26 / versionName=0.26

### 多选手势改为方向判定（v0.25）
- 废弃 v0.22 的「速度阈值」，改为手机厂商相册同款**方向判定**：
  - **横向滑动**（`|dx| > |dy|`，即 45° 为分界）= 快捷多选，起点到当前点的矩形覆盖到的照片全部选中
  - **纵向滑动**（`|dy| ≥ |dx|`）= 滚动图片列表
  - **判定一次即锁定**：离开起点 20px 时判定方向，之后整个手势不再改变 —— 横向滑动后不松手再纵向滑动，仍然只是扩大选取矩形，不会切成滚动
  - 纵向判定时补发判定前那段 `dy`，起手不丢位移
  - 轻点（位移 < 8px）= 切换单张选中；全程不画框
- 列表项滚出屏幕被回收时清除其命中矩形，避免划选误中屏幕外照片
- versionCode=25 / versionName=0.25

### 表冠灵敏度扩展到 10x（对数轴）+ 系统删除照片（v0.24）
- **灵敏度上限 3.0x → 10.0x**：高倍率下转一格能快速扫过整屏，慢速表冠也能用
- **滑杆改为对数轴**：位置 0~1 等比映射到 0.1x~10.0x（`speed = 0.1 × 100^t`）
  - 线性轴时 0.1x~1.0x 只占滑杆 9%，轻拨就跳过；对数轴下每段拨动的「倍数变化比例」相同（0.1→0.2 与 5→10 距离一致），低频段可精细调
  - 显示格式：< 1x 保留两位（0.15x），≥ 1x 保留一位（2.5x / 10.0x）；滑杆两端标注 0.1x / 1.0x / 10.0x
- **删除改为调用系统删除**：之前直接 `ContentResolver.delete`，Android 11 对非本应用创建的照片会抛 `RecoverableSecurityException`，被 catch 吞掉 → 表现为"删不掉"
  - 现在用 `MediaStore.createDeleteRequest()`（API 30+ 官方推荐）生成系统确认弹窗，用户在系统界面点"删除"后**由系统执行删除**，不需要 `WRITE_EXTERNAL_STORAGE` / `MANAGE_EXTERNAL_STORAGE`
  - IntentSender 通过 `StartIntentSenderForResult` 拉起，带自增 id 保证每次都能触发；用户取消则保留选中并提示"已取消删除"
  - 应用私有目录导入的照片（file://）不进系统弹窗，确认后一并删除
  - API < 30 或系统弹窗拉不起来时，回退到直接删除并给出明确提示
- versionCode=24 / versionName=0.24

### 表冠消除反向回弹、对齐 f-x 手感（v0.23）
- 用户反馈："f(x) 滚动很平滑，相册滚动完像有回弹，总是向反方向滚一小段"，逐行对比 f-x 找到三处差异并全部对齐：
  - **去掉 OPPO 自适应增益**：旧代码 `|v| ≤ 2 → v*15`，把表冠停下瞬间的微小反向抖动放大成十几像素的反向跳动；改为照搬 f-x 直接返回原始轴值，滚动量统一交给灵敏度 `crownSpeed` 调节
  - **关掉过度滚动回弹**：Material3 的 `LazyVerticalGrid`/`LazyColumn` 滚到边界会 stretch 再 spring-back（内容 padding 很大，频繁触边），是"反方向弹一小段"的主因；用 `CompositionLocalProvider(LocalOverscrollConfiguration provides null)` 显式关闭，对齐 f-x Material2 LazyColumn 的硬停止手感
  - **直接 scrollBy**：由 `gridState.scroll { scrollBy }` 改为 `gridState.scrollBy(step)`（与 f-x `listState.scrollBy` 一致），不走会触发 fling/overscroll 的 ScrollScope
- 相册、设置列表、更新页三处统一；多选、缩放、表冠采集双模式不变
- versionCode=23 / versionName=0.23

### 多选手势：速度阈值 + 矩形区域填充（v0.22）
- **速度阈值判定**：多选模式下拖动离开起点约 20px 后，按这段平均速度分类手势（阈值 0.5 px/ms）
  - 慢速拖动（<阈值）= 滚动列表：增量投递到普通协程再 `scrollBy`，跟手滚动
  - 快速拖动（≥阈值）= 复选照片：判定一次即锁定到手势结束，避免忽快忽慢来回切换
  - 手势不可用 `gridState.scroll{}`（受限协程作用域），故滚动增量走 MutableSharedFlow 转普通协程执行
- **矩形区域填充**：快速拖动取「起点→当前位置」形成矩形（各边 +3px，保证纯横/竖划也命中），凡矩形覆盖到的照片全部加入选中
  - 从左上角划到右下角 → 整个几×几区域全选，正是手机厂商相册同款效果
  - 全程不画可见框；轻点仍切换单张选中；长按进入多选、复选圈、底部删除栏不变
- versionCode=22 / versionName=0.22

### 设置列表对齐 Wear OS 官方机制（v0.21）
- 参照官方 TransformingLazyColumn + Button(fillMaxWidth) + SurfaceTransformation
- 根因：旧版把居中按钮放大到 1.3 倍，而 graphicsLayer 绘制层缩放不改布局占位，按钮膨胀侵入固定间距导致重叠、看起来和没改一样
- 改为「只缩不放」：缩放系数始终 ≤ 1（居中 1.0 → 边缘 0.7），按钮满宽、居中正常大小、边缘缩小淡出
- 按钮永远待在布局框内，间距恒定、不再重叠；视觉上即官方圆屏设置列表效果

### 表冠滚动照搬 f-x、去掉阻尼（v0.21）
- 参照用户项目 vveyin/f-x 的表冠消费方式：`rotary.collect { scrollBy(-amount * ROTARY_SCROLL_FACTOR) }`，FACTOR=1.0
- 撤销 v0.16 起的 SmoothCrownScroll（事件累加成目标位移 + 每帧阻尼逼近 22%）——停手后还会滑行的阻尼感
- 改为 CrownScroll：事件到达直接 scrollBy，转多少滚多少、停手即停，无阻尼、即时跟手
- 相册网格、设置列表、更新页三处统一；采集层（OPPO/华为三星双模式、自适应增益）不变
- 照片列表、多选刷选不变

### 滑动刷选改为手机相册同款（v0.20）

- **顶部跳变修复**：照片与设置按钮滚出屏幕顶部后 `cy` 变负，旧代码 `cy>=0` 条件失效导致跳过缩放、scale 恢复 1.0「突然变大」；改为测量后始终按距离计算，退出半径加大到 1.05×半屏，平滑渐隐

- **长按多选**：长按照片进入多选模式，右上角显示复选圈（选中实心对勾/未选空心），点击切换单个选中
- **滑动框选（手机相册同款）**：多选模式下拖动形成矩形，起点→当前点范围内的照片全部选中；横向滑动选整排、对角滑动选整个几×几区域，框选过程有边框预览
- **多选底栏**：多选时底部白线（设置抽屉把手）自动隐藏，改为显示已选数量 + 较小的删除按钮 + 取消；删除走 MediaStore/私有文件删除并刷新列表
- versionCode=19 / versionName=0.19

### 整排缩放 / 按钮整体放大 / 间隔减半（v0.18）
- **照片整排连动缩放**：同一排的照片现在共用同一个缩放值（只由所在「行」的 Y 决定），并把 `graphicsLayer` 锚点统一到屏幕水平中线（`TransformOrigin`），整排围绕中线一起放大/缩小，不再是每张照片各自以自身中心缩放导致彼此分开
- **设置按钮恢复整体居中放大**：撤销 v0.17 的「只缩放文字」，按钮整体参与 `scalingItem` 缩放；按钮有较小的基础宽度（0.74 屏宽），居中时放大 1.38 倍 ≈ 满屏，边缘缩到 0.80 —— 「屏幕宽度」是放大后的最大尺寸，而非每项默认宽度
- **间隔减半**：`spacedBy` 12dp → 6dp
- **说明文本只淡出**：标题与诊断长文本用 `scalingItem(scale=false)` 只做 alpha 淡出，避免放大后溢出圆屏
- versionCode=18 / versionName=0.18

### 按钮间隔固定 / 撑满屏宽（v0.17）
- **间隔固定根因**：旧代码用 `graphicsLayer` 缩放整个按钮，绘制层缩放不改变布局占位，按钮放大时向外膨胀侵入固定间隔，导致间隔忽大忽小/重叠
- **外框尺寸定死**：按钮宽度改为撑满屏幕（`fillMaxWidth`）、高度固定，外框不再参与缩放；间隔由 `spacedBy` 恒定，与滚动位置无关
- **聚焦改为内容缩放**：新增 `focusScale`，只缩放按钮内的文字/图标（居中 1.12→边缘 0.82）保留居中放大感，但不再影响按钮外框和间隔；`scalingItem` 保留 alpha 淡出
- versionCode=17 / versionName=0.17

### 表冠滚动平滑化（v0.16）
- **离散事件改阻尼逼近**：根因是物理表冠每"咔哒"才上报一个事件，旧代码把每个事件瞬间 `scrollBy` 约 135px、无任何插值，肉眼必然一格一格。新增通用 `SmoothCrownScroll`：先把离散增量累加成目标位移，再用逐帧阻尼循环（每帧逼近 22%）把每一跳摊成连续滑行
- **全端统一**：相册网格、设置缩放列表、更新页三处滚动全部改用平滑控制器，手感一致；快速连转持续跟手，停手后平滑追停
- **保留浮点增量**：`pushCrown` 不再"攒够 1 格才发、发完连余数清零"，每个浮点增量（含 0.2~0.8 小数）原样投递，距离守恒、不再量化丢步
- versionCode=16 / versionName=0.16

### 抽屉式设置 / 双向手势动画 / 按钮尺寸（v0.15）
- **按钮尺寸修复**：收敛缩放幅度（1.28→1.14）、加大条目间距（6→12dp）、按钮限宽居中，解决"放大后显示不全 + 条目重叠"
- **设置改常驻抽屉**：设置不再是导航栈中的一页，而是常驻在主界面之上的抽屉，避免进出时的生硬页面切换
- **底部上滑展开**：主界面底部白色半透明细线，上滑时抽屉跟手升起、松手带动画吸附展开
- **顶部下滑收起**：设置一级菜单顶部有同样的细线，下滑时抽屉跟手降下、松手动画吸附收起；二级菜单不响应下滑，靠右划返回一级
- **进出动画**：展开/收起用 tween 缓动，拖动全程 snapTo 跟手，不再是突然出现/消失
- versionCode=15 / versionName=0.15

### 设置控件 / 上滑设置 / 返回动画（v0.14）
- **设置控件改标准按钮**：设置主页与二级菜单统一改用 Material3 全圆角 Button（紧凑 42–46dp），不再是大块卡片
- **设置新增入口**：「关于」上方新增「检测更新」，另加「导入照片」，补齐主页移除顶部按钮后的功能入口
- **主页底部上滑开设置**：删除主页顶部三个按钮（导入/更新/设置），改为从屏幕底部上滑打开设置，底部中央有一条白色半透明引导线，跟手上移变亮
- **返回过渡动画**：右划返回时当前页跟手右移淡出、底层缩放回正；松手超阈值先把当前页完整滑出再切换页面，不再"划过去突然消失"
- versionCode=14 / versionName=0.14

### 表冠平滑 / 层级黑底 / 居中缩放校准（v0.13）
- **表冠小数累积**：`pushCrown` 把不足 1 格的小数增量累积起来，攒够整格再投递（余数留下），避免小数像素在滚动中被丢弃导致的不平滑
- **每页纯黑背景**：导航栈的每一层都垫不透明纯黑底，缩放条目 alpha 淡出时不再透出下层画面（修复"设置页能看到相册内容"）
- **层级表冠隔离**：底层界面传空表冠流，转一次表冠只滚当前页，不再同时滚动相册和设置两个列表
- **居中缩放校准**：改用条目的真实屏幕坐标（`positionInRoot` + 屏幕高度）计算缩放，最大项严格落在屏幕正中心，修复此前"最大出现在屏幕偏下三分之一"
- versionCode=13 / versionName=0.13

### 正方形网格 / 二级菜单缩放 / 交互式返回（v0.12）
- **正方形网格相册**：列表项改为正方形卡片（`aspectRatio(1f)`），占位不再随屏宽拉成长条
- **每排张数可配置**：设置 →「每排照片」点击在 2/3 张间切换，存 SharedPreferences，默认 2 张；网格用 `LazyVerticalGrid(GridCells.Fixed(columns))`，按行到屏幕中心的距离做温和缩放
- **设置二级菜单居中放大**：表冠适配、主题、扫描诊断三个子页全部改用全屏 `ScalingScrollColumn`，与主设置页一样有居中放大 + 表冠滚动（此前只有主页有）
- **更新页适配表冠**：检查更新页滚动改为表冠可驱动，长更新说明可转表冠浏览
- **交互式返回**：用返回栈 + `SwipeBackContainer` 替代简单位移，右划时当前页跟手右移淡出、**下层实时渲染返回目标界面**（如大图返回露出相册、编辑返回露出大图），松手超阈值完成返回，否则回弹
- versionCode=12 / versionName=0.12

### 缩放"中间小、两边大"修复（v0.11）
- **根因一：缩放项错位**：列表顶部有一个"加载更多"footer 占了 index 0，`itemsIndexed` 给照片的 index 与 `visibleItemsInfo` 里的 index 整体错开一位；中心那张卡片实际拿到的是它上面那张的 offset 去算缩放，于是"中间小、旁边大"
- **根因二：draw 不重算**：`graphicsLayer{}` 只读 `layoutInfo`，LazyColumn 滚动通常只移动布局位置、不 invalidate item 自身的 draw，缩放值停留在 item 首次进入可见区那一刻（那时在边缘→小），滚到中间仍是小的
- **修复**：匹配改用照片 uri 作 key（不受 footer 占位影响）；draw lambda 中显式读取 `firstVisibleItemIndex`/`firstVisibleItemScrollOffset` 两个 SnapshotState 强制每帧重算；缩放曲线改为基于 item 自身高度归一化 + 二次缓动，中心 1.28x、相邻明显更大、边缘淡出，settings 列表同步修正

### 缩放列表与手势（v0.10）
- **缩放方向修正**：中间卡片最大（1.12x）、越靠上下边缘越小并淡出；锚点固定为屏幕中心，按到中心的距离每帧计算，滚动连续，不再"从最小突然变最大"
- **设置主页改为全屏缩放列表**：与主相册一致的 Wear OS 效果，条目中间大两边小，表冠可滚
- **全界面边缘右划返回**：去掉所有左上角返回键，改为从左边缘右划返回（带跟手位移+淡出），覆盖查看/编辑/设置/更新页

### 重复 key 崩溃修复（v0.9）
- **根因**：列表用照片 `_ID` 作 Compose key，同一张照片被多个存储卷索引时 uri 不同、id 相同，按 uri 去重没能去掉重复 id，Compose 遇到重复 key 抛 `IllegalArgumentException` 直接崩溃
- **修复**：列表 key 改用 uri（已去重，天然唯一）；数据层合并时增加 id 去重；大图翻页定位也改用 uri 保持一致
- 崩溃日志机制（v0.8）验证有效：完整抓到了堆栈与设备信息

### 崩溃检测与日志（v0.8）
- **全局崩溃捕获**：自定义 Application 在最早时机安装 UncaughtExceptionHandler，主线程/子线程异常、Compose 组合异常都写进内部日志（含堆栈、线程、设备、版本、时间戳）
- **崩溃报告页**：检测到上次异常退出后，启动第一屏强制显示，带「复制日志 / 清除日志 / 继续进入」按钮 —— 即使一打开就崩，用户也能拿到日志
- **设置页「复制日志」**：正常进入时也可随时复制完整运行日志
- **breadcrumb**：记录启动阶段关键节点，便于定位崩在哪一步

### 更新源与下载（v0.7）
- **主源改为 Gitee**：`https://gitee.com/vveyin/WatchGallery`。GitHub Release 资产会 302 跳到 `release-assets.githubusercontent.com`，该域名国内常被限速/阻断，这正是"下载进度条一直不动"的根因
- **三层下载地址**：Gitee 直链 → GitHub 官方直链 → 国内加速镜像（ghfast.top / gh-proxy.com），前一个失败自动换下一个
- **断点续传**：半截中断后重试从断点继续
- **字节进度**：服务器不给 Content-Length 时显示"已下载 X MB"，不再出现 0% 不动
- 检查更新：Gitee 优先，失败回落 GitHub

### 分页加载（v0.6）
- **主页一直转圈修复**：MediaStore 已查到照片时跳过全盘目录遍历（逐个 stat 几千文件很慢）；只有媒体库为空才做目录兜底
- **分页加载**：主页先显示前 30 张，滑到底部再追加，底部提示已显示 X/Y 张；点开大图仍可翻全部 1324 张

### 显示与交互调整（v0.5）
- **照片列表改为 Wear OS 风格全屏缩放列表**：去掉圆屏矩形安全区，列表占满整屏，靠「中间大、两边小并淡出」的缩放效果避开表盘弧边（等同原生 ScalingLazyColumn 观感）
- **设置页列表接入表冠**：设置主页、表冠适配、主题、扫描诊断各页现在都能用表冠滚动（之前只能用触摸）
- 本版 versionName 0.5，versionCode 保持 5（检查更新已改为按 versionName 比较，不受影响）

### 检查更新修复（v0.4）
- 旧逻辑拿 GitHub tag 解析出的序号（v0.3 → 3）跟 APK 的 `versionCode`（v0.2 的 versionCode 是 3）比较，编号体系不同，导致装了 v0.2 时把线上的 v0.3 误判为"已是最新版本"
- 现在比较双方统一从 `versionName` 的小数部分提取序号（0.2 → 2、0.3 → 3、0.15 → 15），不再使用 `versionCode`
- "已是最新版本"页同时显示本机版本与线上版本，便于确认是否真的请求到了 GitHub

### 版本号规则
从 `0.1` 起持续递增：`0.1 → 0.2 → … → 0.15 → 0.16 → 0.17 → …`，versionCode 同步 +1，每个版本打 tag 并发布到 GitHub Releases。

### 检查更新（v0.1 新增）
- 通过 GitHub Releases API 检查新版本（仓库地址由 BuildConfig 注入）
- 发现新版本进入下载页：显示版本信息、更新说明、**下载进度条**
- 下载完成显示**安装按钮**；APK 保存在稳定路径，安装失败返回后可**再次点击安装**，不会丢失安装包
- 需系统允许「安装未知应用」权限

## 技术栈

## 构建

```bash
# 需 Android SDK platform 34 + build-tools 34.0.0 + JDK 17+
./gradlew assembleRelease

```

签名使用项目根目录 `watchgallery.jks`（别名/口令见 `app/build.gradle.kts`，仅供测试，正式发布请更换）。
