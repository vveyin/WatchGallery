# 相册 · WatchGallery

一款专为 **Android 11 圆屏手表**（运行完整 Android，非 Wear OS）设计的相册应用。UI 风格借鉴 GitHub 用户 vveyin 的 `f-x` 仓库（Material Design 3、圆表盘自适应、旋转表冠操作、夜间/白天双主题），相册与编辑功能对标手机相册（参考 Fossify Gallery、ImageToolbox）。

## 功能

### 相册
- 通过 MediaStore 扫描设备全部图片，按文件夹（相册）分组
- 圆屏 2 列 / 方屏 3 列网格自适应，图片安全区避让表盘边缘
- 大图查看：双指缩放、单指平移、双击复位、上下滑动切换、表冠缩放
- 权限申请（Android 13 `READ_MEDIA_IMAGES` / 低版本 `READ_EXTERNAL_STORAGE`）

### 图片编辑（对标手机相册）
- **滤镜**：原图 / 黑白 / 怀旧 / 鲜艳 / 冷色 / 暖色 / 反色
- **调节**：亮度、对比度、饱和度、色温
- **裁剪**：拖动选择区域
- **涂鸦**：多色画笔、粗细、撤销、清空
- **旋转/翻转**：90° 旋转、水平/垂直翻转、重置
- **保存**：通过 MediaStore 存入 `Pictures/WatchGallery`，无需存储权限（API 29+）

### 主题与交互
- Material 3 主题，夜间（默认黑底）/ 白天（白纸）/ 跟随系统三态切换，设置页可选
- 沉浸式全屏，表盘安全区自适应（借鉴 f-x 的 WatchMetrics 弧宽/短边缩放思路），所有页面内容约束在内切圆内
- 旋转表冠 / 滚轮 / 方向键 / 音量键多路上报

### 设置（v0.1 新增）
- **表冠适配**（完整借鉴 f-x 的两种模式）：
  - `OPPO`：走普通 MotionEvent 滚轮轴，不过滤 action/source（OPPO 系表冠 source 位不可靠）
  - `华为 / 三星`：走 `ACTION_SCROLL` + `SOURCE_ROTARY_ENCODER`，原始值 ×15 拉齐手感
  - **灵敏度**：0.1x ~ 10.0x，**对数轴**调节（0.1→1 与 1→10 拨动距离相同，低频段也能细调），乘在原始滚动量上，改完即时生效并持久化
  - **表冠测试**：页内实时显示收到的表冠事件，便于确认哪种模式适配你的表（v0.2）
- 主题设置：夜间 / 白天 / 跟随系统

### 稳定性修复（v0.2）
- **权限检测**：每次回到前台重新探测；被拒且「不再询问」时提供「去系统设置」入口；空相册可「重新扫描」
- **读不到照片兜底**：MediaStore 缺列不再导致整表为空；额外直接扫描 `Pictures/DCIM/Downloads` 常见目录
- **表冠 OPPO 模式**：修复增量被累加成总位移导致滚到底后失效的问题，改为逐条事件流投递；旋转编码器式表冠自动增益

### 相册空白修复（v0.3）
- **布局根因**：标题栏的安全区容器 `fillMaxSize` 放在 `Column` 里会吃掉整屏高度，网格高度被压成 0，看起来就是"照片列表是空的"。现在整屏统一套安全区，标题 wrap content、网格 `weight(1f)`
- **安全区改为几何正确**：圆内最大可完整显示的区域是以圆心为中心的正方形（≈0.707×直径），不再只是加 padding 导致四角被弧边切
- **读取照片五级兜底**：images 表逐卷查询 → files 表 `media_type=IMAGE` → 主动触发系统媒体扫描（adb push 的照片不进媒体库）→ 目录直扫 → 应用内导入目录
- **手动导入**：空相册可直接用系统文件选择器导入照片，内容复制进应用私有目录，永远读得到
- **扫描诊断页**：设置 → 扫描诊断，展示权限、媒体库行数、目录命中、异常信息

### 抽屉统一为 f-x 做法 / GIF / 文本框 / 清晰度（v0.42）
- **三处抽屉（设置、查看图片、编辑）统一成 f-x 的 `DrawerState`**：一个 `progress ∈ [0,1]` 的单一 Float 状态 + 一条可取消的弹簧协程（`spring(dampingRatio = 0.90, stiffness = 520)`）驱动 `translationY = (1 - progress) × 屏高`
  - 拖动只累加**相邻两帧的位移差** `position.y - previousPosition.y`，不用「当前 y − 按下 y」，面板自身跟着移动时局部坐标不会反向抵消
  - 松手判据「方向优先、距离兜底」：快速上甩开、下甩收，位移超过 6% 即按方向定，否则看是否过半 —— 手表屏幕小手拖不到半屏，不再弹回
  - 不再每帧 `launch` 动画协程，旧值后到造成的抖动/抽搐一并消失
- **退出大图的「抽搐」**：查看页退出时缩略图会短暂被一张按正方形拉伸的图顶替。现在列表格子的 `ImageRequest` 显式带上格子的像素尺寸（`size(cellPx, cellPx)`），解码按格子比例来，退出时只会是缩略图本身
- **大图清晰度随缩放提升**：解码尺寸从「屏幕宽度」提到 3 倍（上限 1600px），放大后不再是一张被拉大的小图
- **查看页抽屉**：顶部一行显示图片名；下面三个按钮「编辑 / 详细信息 / 重命名」。详细信息弹窗给出名称、尺寸、大小、日期、文件夹、类型；重命名走 `MediaStore` 改 `DISPLAY_NAME`，遇到 `SecurityException` 自动拉起系统写权限弹窗
- **GIF**：接入 `coil-gif`（`GifDecoder` + `ImageDecoderDecoder`），列表和查看页都能播动图；设置里新增「列表显示动图」开关 —— 关闭时列表用 `BitmapFactoryDecoder` 只解静态首帧，查看页**始终**是动图
- **进入大图不再黑一下**：大图层背景改为 `Color.Transparent`，黑底用 `drawBehind { drawRect(黑, alpha = 入场进度) }` 只失效绘制；相册层常驻不卸载（`SwipeBackContainer(backContent = {})`），图片完全铺满屏幕后列表才被盖住
- **点击图片不弹名字**：单击只处理双击复位，名字只在抽屉顶部出现
- **编辑页**：保存/返回全部进抽屉，样式换成 Material `Button`/`OutlinedButton`，抽屉拉下去屏幕上只剩一张图；图片支持双指缩放、表冠缩放、「缩放按键」开关同步生效；进入涂鸦/框选后单指仍是画笔、双指才是缩放
- **文本框**：抽屉里选「文本」后点图片任意位置落一个文本框并进入输入；点别处失焦，空内容自动丢弃、有内容保留；再次点击文本框重新获得焦点，文字周围出现**半透明描边**（按所在位置图片亮度选色：亮处用灰、暗处用白，避免和背景糊在一起），文字随图片一起缩放、保存时烧进位图

### 抽屉把手贴顶 / 拖不动修复（v0.40）
- **把手回到抽屉顶边**：上一版把手被放在内容块的第一行，而内容整体垂直居中，结果白线跑到了屏幕中间。现在把手固定在面板最上沿（随面板滑入滑出），内容用上下两个 `weight(1f)` 居中
  - 编辑页的保存按钮下移到把手下方 30dp，两者不再重叠
- **修好「拉上来就划不下去」**：拖动手势写在面板自己身上，而面板是靠 `graphicsLayer` 的 `translationY` 移动的 —— `pointerInput` 拿到的 `position` 是**面板局部坐标**，面板跟着手指下移多少，同一根手指的局部 y 就跟着减多少，两者正好抵消，算出来的位移恒为 0，于是面板纹丝不动
  - 改法：把局部 y 加回当前的 `translationY` 换算成屏幕 y 再求差（`dy = (局部y + 位移) - (按下局部y + 按下位移)`），位移就还原成真实的手指行程
  - 编辑页、查看页两处抽屉同一处理

### 编辑 / 大图抽屉统一为两态 + 背景整屏对齐（v0.39）
- **编辑页抽屉改成和设置一样的两态**：不显示（屏幕上只留底部一条白线）/ 全屏铺开。工具行、选项行、调节滑杆一次全摆出来，不再有几档吸附、也不用担心「拖不到底」或「内容被屏幕挡住」。从底部白线上滑即全屏，在面板任意位置下拉、或轻点面板顶部的把手即收起
- **编辑页背景改成「屏幕等价图」的模糊版**：先按屏幕尺寸合成一张图 —— 黑底 + 图片画在它**实际显示的矩形**里（圆屏取内切圆内最大矩形），再整体模糊。以前是直接糊原图，原图按自己比例铺满，和上层显示出来的图片大小、位置都对不上，抽屉里的画面看着像另一张图
  - 合成量用的是布局的实际像素（不是 `LocalConfiguration` 的屏幕尺寸），背景与图片严丝合缝
  - 拖调节滑杆时预览图连续变化，延迟 80ms 再算，避免把算力全花在中间态上
- **大图页抽屉同样改成两态**：不显示 / 全屏。全屏面板里是功能列表（现在只有「编辑」，以后加功能直接往下排），从底部白线上滑打开，下拉或轻点把手收起
- **背景绘制统一铺满**：`BlurBand` 不再用 `LocalConfiguration` 换算，直接把整屏图铺到这张 Canvas 上（Canvas 本身就是整屏），像素坐标与屏幕一一对应，圆屏边缘也不会错位

### 编辑抽屉拖不到底 / 抽搐修复（v0.38）
- **抽搐的根因**：拖动是在 `awaitEachGesture` 的「受限挂起作用域」里跑的，调不了 `Animatable.snapTo`，只能每帧 `scope.launch` 一个协程去设值。主线程一忙，排队的旧值就晚于新值执行，面板来回跳；松手后残留的协程还会把刚吸附好的档位又拉回去
- **改法**：抽屉位移换成普通 `Float` 状态 —— 拖动里直接赋值（同步、零延迟），松手再用一个可取消的 `Job` 跑 240ms 吸附动画。位移只被绘制阶段读取（`graphicsLayer` / `Canvas`），拖动过程中一次重组都不会发生
- **拖不到底**：原来只有 30dp 的把手能拖，圆屏底部可下滑的行程不够 92dp，永远吸附不回最低档。现在**整块抽屉面板都能上下拖**，把手只负责轻点逐档
- **拉起热区常驻**：之前按 `panel > 0` 做条件渲染，刚一拉动节点就被移出组合、`pointerInput` 协程连带取消，手感是「拉一下就断」。现在热区一直在组合里，只有底部那条白线跟着收起状态显示/隐藏

### 背景固定不动 / 抓图剔除抽屉 / 编辑抽屉修复（v0.37）
- **抽屉背景不再跟着抽屉跑**：三处抽屉的背板都改成「固定在屏幕底层的整屏模糊图 + 只露出抽屉覆盖的那一段」。拖动时背景里的色块是钉死的，只有揭开范围在变 —— 看起来是一块玻璃板在图片上滑动，而不是一张背景图跟着面板一起升起来。做法是整屏画一次、用 `clipPath` 裁出底部一条，图按整屏坐标底边对齐，所以像素位置恒定
- **抓背景时不再把抽屉拍进去**：新增「抽屉可见」门（`BlurBackdrop.setCovered`），抽屉一开始移动就关门、所有抓图请求（包括排队的延时刷新）全部丢弃，等面板完全滑出屏幕才开门补一帧。之前是「落位后 100ms 再抓一张」，那一帧里已经有「编辑」按钮，糊完就成了一块残影
  - 设置抽屉：手指按下把手时抓（此刻抽屉还在屏幕外）、收起后补拍
  - 大图页：进页面 / 切图后（抽屉确定收起）抓，打开抽屉期间一律不抓
  - 编辑页：直接**用图片自己**缩到 1/4 再糊，完全不依赖抓屏 —— 抽屉初始就露着工具栏，抓屏无论如何都不干净
- **编辑页抽屉恢复可用**：上一版把抽屉初始位移设成了「完全收起」，面板整个滑到屏幕外，于是白色把手线和拖动热区一起消失，看起来就是「抽屉拉不起来」。现在初始停在工具栏档（92dp），另外抽屉完全收起时屏幕底部常驻一条白线 + 上滑热区，随时能再拉起来
- 编辑页抽屉档位微调为 0 / 92 / 152 / 200（dp），把手线改成白色半透明（在深色图片和模糊背景上都看得见）

### 设置形变回归 / 抽屉多档吸附 / 毛玻璃背景（v0.36）
- **设置条目恢复居中放大**：正中间 1.12 倍、上下边缘 0.76 并淡出，回到 Wear OS 那种有层次的设置列表。滚动**只改大小和透明度、不改颜色**，所以不会像旧版那样被误读成「这一条被选中」；手指按下时底色向主色偏一点并轻微回缩，点击反馈明确
- **二级菜单转场动画**：一级 ↔ 二级改成横向滑入滑出 + 淡入淡出（260ms），返回时方向相反；左缘右划仍可返回一级。一级菜单的滚动位置会保留，回来还停在原处
- **大图入场动画即时播放**：点下去那一刻动画就开始 —— 第一帧直接用列表里**已经解码好的缩略图**铺满、按原缩略图位置放大，大图解码完成后再淡入替换。旧版要等大图解码完才动，看起来像点了没反应
- **编辑页抽屉重写**：
  - 图片不再被抽屉推挤或缩小，抽屉改成**盖在图片下半部分**的一层玻璃板
  - 抽屉 4 档可停：收起 / 工具栏 / 工具 + 选项 / 全开。拖动跟手、松手吸附最近一档；轻点把手逐档展开、到顶再点收起，单指就能用
  - 内容重新排版得更宽松（胶囊 44dp、行距 8dp、左右留白），修掉「下面几行被屏幕挡住」的问题；选中工具后自动升到能看见它选项的那一档
- **毛玻璃抽屉背景**：设置 / 大图 / 编辑三处抽屉统一用静态模糊背景。做法与 f-x 一致：`PixelCopy` 抓一帧 → 缩到 1/3 → RenderScript 高斯模糊（没有 RS 驱动时退回纯 Kotlin 盒式模糊）→ 之后每帧只画这张图，滚动和拖动都是零卷积
  - 抓图时机：手指按下抽屉那一刻（抽屉还在屏幕外，拍到的是干净底层）；落位后 100ms 再补一帧
  - 单指操作、抽屉静止时背景本来就不该变，所以静态刷新不会穿帮
- **新增「模糊背景」开关**：设置里可关，关掉后三处抽屉退回纯色背板（老设备可以省点 GPU）

### 编辑页重做 / 大图入场动画 / 更新页改版（v0.35）
- **设置条目去掉滚动高亮形变**：表冠或手指滚动时，条目不再「居中放大、上下缩小淡出」。那套形变容易被误读成「当前这条被选中」，现在设置页所有条目尺寸与透明度恒定
- **检查更新页重写**：改成与设置页同一套视觉 —— 缩放滚动列表 + 一张淡灰底状态卡（圆角图标徽章、标题、版本号、更新说明）+ 满宽药丸按钮；下载进度条放进卡里，错误态用 error 色，不再有整块紫色大按钮
- **新增「缩放按键」开关**：设置 → 缩放按键。关掉后查看大图时顶部不再显示放大/缩小按钮，双指与表冠缩放照常可用
- **大图入场动画**：点图片不再瞬间切换。大图从被点击的那张缩略图位置放大到全屏，280ms 缓动 + 淡入；取不到缩略图矩形时退化为轻微放大淡入
- **编辑页整体重做**：
  - 图片按「圆内可容纳的、与图片同比例的最大矩形」显示，比原来被顶栏 + 常驻工具面板挤压时大很多；抽屉展开时图片自动上移让位，永不被遮住
  - 所有功能收进底部抽屉，抽屉里是一条**横向列表**：滤镜 / 调节 / 裁剪 / 涂鸦 / 旋转，左右滑动选择；选中「调节」后同一行换成四个参数，下方多一条细滑杆
  - 裁剪框改存原图坐标（修正之前裁剪区域与保存结果对不上的问题）；旋转或翻转会清掉旧裁剪框，避免裁到错误位置
  - 涂鸦不再烘焙进预览位图（否则每画一个点都要重算整张图），改为 Canvas 叠加实时绘制，手感明显更跟手

### 图标重绘 + 自适应图标（v0.34）
- **整体重画桌面图标**：不再是纯色块 + 硬边三角形
  - 背景：紫→靛的对角渐变，左上柔光、底部暗角，做出体积感
  - 主体：一张白色圆角「照片卡」浮在背景上（柔和投影），照片里是蓝紫天空、金色太阳和两座白雪山
  - 细节：照片区一圈很淡的内阴影，形成「照片嵌在相框里」的凹陷；太阳带暖色光晕；卡片四周白色留边
- **新增 adaptive icon**（`mipmap-anydpi-v26`）：背景层渐变 + 前景层图形分开，
  系统裁圆/裁圆角时不会切到内容，手表桌面上观感与系统应用一致
- 补齐 `xxxhdpi` 图标，48/72/96/144/192 五个密度全部重新生成（2048px 超采样后 LANCZOS 缩小，边缘干净）

### 大图翻页动画 + 相邻照片预加载（v0.33）
- **翻页跟手 + 缓动动画**：上下滑动时三张图组成一整条跟着手指走，松手后按位移吸附（超过屏高 16% 切一张），
  剩余距离用 220ms 缓动补完，不再是「一下就跳过去」
- **切图不再卡**：相邻的上/下一张**常驻渲染树**，进入大图时就已经解码完成，切图只是改位移，

### 修复「松手才卡、几秒后崩溃」的真凶：awaitEachGesture 空转 + 主线程看门狗（v0.28）
- **根因**：`awaitEachGesture` 的内部实现是 `while (isActive) { awaitPointerEventScope { block() } }`。
  v0.27 的拖动接续协程在 block 的**第一行**就写了 `if (selectionMode) return@awaitEachGesture`，
  于是在多选模式下 block 还没碰到任何挂起点就返回，下一轮立刻再次调用它 —— 变成**没有挂起点的
  忙循环**，把 `AndroidUiDispatcher.Main` 彻底占满。
  - 手指按着时协程正挂在 `awaitPointerEvent` 上，所以拖动过程还看着正常；**一松手**循环就开始空转，
    屏幕上每个可见单元格各跑一个 → 界面立即卡死，几秒后 ANR，系统杀掉进程，日志里只剩 `START`
  - 修复：把 `awaitFirstDown()` 提到状态判断**之前**，保证每一轮 block 至少挂起一次等手指按下；
    多选模式下直接 return 只是「等下一次按下」，不再空转
- **新增主线程看门狗** `util/MainThreadWatchdog.kt`：ANR 不经过 `UncaughtExceptionHandler`，
  所以卡死永远抓不到堆栈。现在后台守护线程每 1s 往主线程投一次心跳，超过 2.6s 未执行即判定阻塞，
  抓取主线程堆栈写入崩溃日志并置位 `crash.pending`，下次启动的崩溃报告页就能直接看到卡在哪一行

- **间隔固定根因**：旧代码用 `graphicsLayer` 缩放整个按钮，绘制层缩放不改变布局占位，按钮放大时向外膨胀侵入固定间隔，导致间隔忽大忽小/重叠

- **聚焦改为内容缩放**：新增 `focusScale`，只缩放按钮内的文字/图标（居中 1.12→边缘 0.82）保留居中放大感，但不再影响按钮外框和间隔；`scalingItem` 保留 alpha 淡出
- versionCode=17 / versionName=0.17

### 表冠滚动平滑化（v0.16）
- **离散事件改阻尼逼近**：根因是物理表冠每"咔哒"才上报一个事件，旧代码把每个事件瞬间 `scrollBy` 约 135px、无任何插值，肉眼必然一格一格。新增通用 `SmoothCrownScroll`：先把离散增量累加成目标位移，再用逐帧阻尼循环（每帧逼近 22%）把每一跳摊成连续滑行
- **全端统一**：相册网格、设置缩放列表、更新页三处滚动全部改用平滑控制器，手感一致；快速连转持续跟手，停手后平滑追停
- **保留浮点增量**：`pushCrown` 不再"攒够 1 格才发、发完连余数清零"，每个浮点增量（含 0.2~0.8 小数）原样投递，距离守恒、不再量化丢步
- versionCode=16 / versionName=0.16

### 抽屉式设置 / 双向手势动画 / 按钮尺寸（v0.15）
- **按钮尺寸修复**：收敛缩放幅度（1.28→1.14）、加大条目间距（6→12dp）、按钮限宽居中，解决"放大后显示不全 + 条目重叠"
- **设置改常驻抽屉**：设置不再是导航栈中的一页，而是常驻在主界面之上的抽屉，避免进出时的生硬页面切换
- **底部上滑展开**：主界面底部白色半透明细线，上滑时抽屉跟手升起、松手带动画吸附展开
- **顶部下滑收起**：设置一级菜单顶部有同样的细线，下滑时抽屉跟手降下、松手动画吸附收起；二级菜单不响应下滑，靠右划返回一级
- **进出动画**：展开/收起用 tween 缓动，拖动全程 snapTo 跟手，不再是突然出现/消失
- versionCode=15 / versionName=0.15

### 设置控件 / 上滑设置 / 返回动画（v0.14）

- **设置新增入口**：「关于」上方新增「检测更新」，另加「导入照片」，补齐主页移除顶部按钮后的功能入口
- **主页底部上滑开设置**：删除主页顶部三个按钮（导入/更新/设置），改为从屏幕底部上滑打开设置，底部中央有一条白色半透明引导线，跟手上移变亮
- **返回过渡动画**：右划返回时当前页跟手右移淡出、底层缩放回正；松手超阈值先把当前页完整滑出再切换页面，不再"划过去突然消失"

### 表冠平滑 / 层级黑底 / 居中缩放校准（v0.13）

- **每页纯黑背景**：导航栈的每一层都垫不透明纯黑底，缩放条目 alpha 淡出时不再透出下层画面（修复"设置页能看到相册内容"）
- **层级表冠隔离**：底层界面传空表冠流，转一次表冠只滚当前页，不再同时滚动相册和设置两个列表
- **居中缩放校准**：改用条目的真实屏幕坐标（`positionInRoot` + 屏幕高度）计算缩放，最大项严格落在屏幕正中心，修复此前"最大出现在屏幕偏下三分之一"

- versionCode=12 / versionName=0.12

### 缩放"中间小、两边大"修复（v0.11）
- **根因一：缩放项错位**：列表顶部有一个"加载更多"footer 占了 index 0，`itemsIndexed` 给照片的 index 与 `visibleItemsInfo` 里的 index 整体错开一位；中心那张卡片实际拿到的是它上面那张的 offset 去算缩放，于是"中间小、旁边大"
- **根因二：draw 不重算**：`graphicsLayer{}` 只读 `layoutInfo`，LazyColumn 滚动通常只移动布局位置、不 invalidate item 自身的 draw，缩放值停留在 item 首次进入可见区那一刻（那时在边缘→小），滚到中间仍是小的
- **修复**：匹配改用照片 uri 作 key（不受 footer 占位影响）；draw lambda 中显式读取 `firstVisibleItemIndex`/`firstVisibleItemScrollOffset` 两个 SnapshotState 强制每帧重算；缩放曲线改为基于 item 自身高度归一化 + 二次缓动，中心 1.28x、相邻明显更大、边缘淡出，settings 列表同步修正

### 缩放列表与手势（v0.10）
- **缩放方向修正**：中间卡片最大（1.12x）、越靠上下边缘越小并淡出；锚点固定为屏幕中心，按到中心的距离每帧计算，滚动连续，不再"从最小突然变最大"
- **设置主页改为全屏缩放列表**：与主相册一致的 Wear OS 效果，条目中间大两边小，表冠可滚
- **全界面边缘右划返回**：去掉所有左上角返回键，改为从左边缘右划返回（带跟手位移+淡出），覆盖查看/编辑/设置/更新页

### 重复 key 崩溃修复（v0.9）
- **根因**：列表用照片 `_ID` 作 Compose key，同一张照片被多个存储卷索引时 uri 不同、id 相同，按 uri 去重没能去掉重复 id，Compose 遇到重复 key 抛 `IllegalArgumentException` 直接崩溃
- **修复**：列表 key 改用 uri（已去重，天然唯一）；数据层合并时增加 id 去重；大图翻页定位也改用 uri 保持一致
- 崩溃日志机制（v0.8）验证有效：完整抓到了堆栈与设备信息

### 崩溃检测与日志（v0.8）
- **全局崩溃捕获**：自定义 Application 在最早时机安装 UncaughtExceptionHandler，主线程/子线程异常、Compose 组合异常都写进内部日志（含堆栈、线程、设备、版本、时间戳）
- **崩溃报告页**：检测到上次异常退出后，启动第一屏强制显示，带「复制日志 / 清除日志 / 继续进入」按钮 —— 即使一打开就崩，用户也能拿到日志
- **设置页「复制日志」**：正常进入时也可随时复制完整运行日志
- **breadcrumb**：记录启动阶段关键节点，便于定位崩在哪一步

### 更新源与下载（v0.7）
- **主源改为 Gitee**：`https://gitee.com/vveyin/WatchGallery`。GitHub Release 资产会 302 跳到 `release-assets.githubusercontent.com`，该域名国内常被限速/阻断，这正是"下载进度条一直不动"的根因
- **三层下载地址**：Gitee 直链 → GitHub 官方直链 → 国内加速镜像（ghfast.top / gh-proxy.com），前一个失败自动换下一个
- **断点续传**：半截中断后重试从断点继续
- **字节进度**：服务器不给 Content-Length 时显示"已下载 X MB"，不再出现 0% 不动
- 检查更新：Gitee 优先，失败回落 GitHub

### 分页加载（v0.6）
- **主页一直转圈修复**：MediaStore 已查到照片时跳过全盘目录遍历（逐个 stat 几千文件很慢）；只有媒体库为空才做目录兜底
- **分页加载**：主页先显示前 30 张，滑到底部再追加，底部提示已显示 X/Y 张；点开大图仍可翻全部 1324 张

- **设置页列表接入表冠**：设置主页、表冠适配、主题、扫描诊断各页现在都能用表冠滚动（之前只能用触摸）

### 检查更新修复（v0.4）
- 旧逻辑拿 GitHub tag 解析出的序号（v0.3 → 3）跟 APK 的 `versionCode`（v0.2 的 versionCode 是 3）比较，编号体系不同，导致装了 v0.2 时把线上的 v0.3 误判为"已是最新版本"
- 现在比较双方统一从 `versionName` 的小数部分提取序号（0.2 → 2、0.3 → 3、0.15 → 15），不再使用 `versionCode`
- "已是最新版本"页同时显示本机版本与线上版本，便于确认是否真的请求到了 GitHub

### 版本号规则
从 `0.1` 起持续递增：`0.1 → 0.2 → … → 0.15 → 0.16 → 0.17 → …`，versionCode 同步 +1，每个版本打 tag 并发布到 GitHub Releases。

### 检查更新（v0.1 新增）
- 通过 GitHub Releases API 检查新版本（仓库地址由 BuildConfig 注入）
- 发现新版本进入下载页：显示版本信息、更新说明、**下载进度条**
- 下载完成显示**安装按钮**；APK 保存在稳定路径，安装失败返回后可**再次点击安装**，不会丢失安装包
- 需系统允许「安装未知应用」权限

## 技术栈
- Kotlin + Jetpack Compose + Material 3
- AGP 8.5.2 / Gradle 8.7 / compileSdk & targetSdk 34 / minSdk 24
- Coil 图片加载、MediaStore 存储、ColorMatrix 色彩处理

## 构建

```bash
# 需 Android SDK platform 34 + build-tools 34.0.0 + JDK 17+
./gradlew assembleRelease
# 产物：app/build/outputs/apk/release/app-release.apk
```

签名使用项目根目录 `watchgallery.jks`（别名/口令见 `app/build.gradle.kts`，仅供测试，正式发布请更换）。
